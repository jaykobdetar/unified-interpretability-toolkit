# Prompt-pair captures

Choose **Two prompts · selected activation differences**, enter prompt A and B, and click **Preview both token lists**. Each string is limited to 2,048 UTF-8 bytes and 1–128 encoded tokens. The preview is an owned disposable tokenizer-only job using the existing pinned tokenizer JSON and installed `tokenizers` library; it verifies the same disk pins but never calls the model loader. It retains the unchanged 4.75 GiB launch gate and the same CPU/process/ownership/deadline controls. No extra model or tokenizer is downloaded.

Review the displayed zero-based token positions, IDs and pieces. Enter one explicit `A,B` position pair per line, at most eight. Both positions must exist; duplicate pairs and implicit truncation are rejected. The suggested pair is the last token of each prompt. Prompt changes invalidate the preview. An SHA-256 digest binds both exact prompts, their encoded IDs and the pinned source model; the worker recomputes it before loading the model. The digest is a freshness check, not an authorization credential. It is omitted from exports when prompts are omitted.

The comparison request has exactly `mode: "prompt_pair"`, `prompts`, `source_model`, `layer`, `activation_site`, `positions` and `preview_digest`. The preview request has exactly `mode: "prompt_pair_preview"`, `prompts` and `source_model`. These modes do not accept edits, generation limits or attention/lens observations. The existing start/poll/cancel/reset API and session capability are reused. Preview completion has its own bounded event and cannot masquerade as generation; preview jobs are not experiment-log entries. The public metadata advertises only fixed limits, never another tab's prompts or preview.

Exactly one model is loaded for the comparison, and its tokenizer wrapper must produce the reviewed IDs. It runs two sequential **uncached prefills**, then exits. One observational hook retains only the selected positions from the selected layer/output: post-block residual, attention component before its residual addition, or MLP component before its residual addition. There is no text generation. A single combined request still has the original 120-second wall / 90 CPU-second limits, 1.5 GiB worker RSS ceiling and memory-reserve stop gate. No automatic retry or expanded time budget is added.

Each of at most eight records contains two 576-value FP32 captures and their difference B−A, computed from the captured values in binary64. At most 24 vector-equivalents are serialized, below the existing 32×576 activation-value budget. Record size stays below the unchanged worker-line bound, and the trace queue remains bounded. L2 norms/distance and cosine are calculated explicitly; cosine is null when either vector norm is zero. Strict helpers recompute differences/metrics before the coordinator accepts a record. Playback shows the difference grid and the two declared positions, with no predicted/generated-token language.

Token equality and equality of the entire consumed prefix through each selected position are distinct labels. Equal tokens can occur in different contexts; different-length prompts do not acquire semantic alignment automatically. The reported difference is a descriptive contextual comparison, not a causal intervention or learned-pattern attribution. The record covers only the selected layer/site/position pairs, not all model layers or tokens.

Opt-in private logs include captures, difference, metrics, selected positions, source/runtime provenance and completion state. Without separate prompt consent, both prompt strings, preview digest, source token IDs and token pieces are omitted. Turning consent off redacts those fields from previously captured history exports too. The captures themselves remain private. The existing eight-record / 1-MiB log cap, visible overflow behavior and explicit manual download remain unchanged. Consent-based browser persistence, selected file journals and local archive import are documented in [Experiment archives](EXPERIMENT-ARCHIVES.md); imports never execute or resume work.
