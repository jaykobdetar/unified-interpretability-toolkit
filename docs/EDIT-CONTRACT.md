# In-memory comparison contract

Output-head and query-row interventions are distinct; see [head sweeps](HEAD-SWEEPS.md).

`POST /api/inference/start` retains `{prompt,max_new_tokens,layer}` for legacy fixed-weight generation. A comparison adds `source_model` (the exact repo, revision and weights SHA-256 object published at `GET /api/inference` in `comparison.source_model`) and `edits`, including an empty list. The source identity is mandatory for comparisons. The coordinator marks its own pinned renderer's `/api/model` response with `inference_source_model`; the UI accepts inspected coordinates only from that marked model. A static Qwen viewer cannot transfer coordinates into the SmolLM2 editor. It offers the separate supported launcher on fresh ports.

At most eight edits; exact object keys only. `tensor` is an allowlisted stored 2-D tensor name, `shape` must match its pinned native shape, `kind` is `rows`, `columns`, or `element`, and `operation` is `zero` or `scale`. Ranges add integer `start,end` and use zero-based **[start,end), end exclusive**. Elements add integer `row,col`. Scale adds a finite numeric `scale` in [-100,100]. Boolean coordinates, shapes, and scales are rejected. Operations compose in list order, including overlaps. No transpose, flattening, padding, or view coordinates are accepted.

The complete stored matrix allowlist is published in `comparison.tensors`. Vectors and an explicit `lm_head.weight` edit are rejected. The stored `model.embed_tokens.weight` is tied to `lm_head.weight`; editing it affects both embedding and output scoring. Runtime architecture, every matrix shape/layout, and storage aliasing are checked before editing. Query projections have 9 heads of 64 consecutive output rows; query head h is rows [64*h,64*(h+1)). K/V projections have 3 heads of 64 rows (grouped-query attention).

The disposable worker loads one pinned CPU FP32 model, runs the baseline, applies edits in memory, and runs the edited branch sequentially with fresh KV state and the same greedy deterministic settings. No model file is written. Worker completion, failure, cancellation and lease expiry dispose of the sole loaded model using the existing ownership/reaping controls. Edits are never applied to a subsequent worker.

Comparison `steps` remain capped at 32. Each has `baseline` and `edited` objects with token ID, full generated token IDs, token piece and generated text, or null if that branch already ended. `candidates` is the union of top-five raw FP32 logits in each branch, at most ten entries, with `{id,baseline_logit,edited_logit,delta}` (edited minus baseline). Both values are gathered even if a token was only top-five in the other branch. `alignment` is `matched_prefix`, `different_prefix`, or `branch_ended`; prefix equality compares consumed token IDs, not text. Later free-running differences under different prefixes combine weight and context effects and are not matched-context causal estimates. A missing branch has null scores/deltas. The existing 576-value activation grid shows the edited branch when present, otherwise baseline; `activation_branch` identifies it.

A `comparison_phase` metadata record indicates baseline versus edited computation. Playback remains independent of compute. Reset/cancel use the session capability and stale responses retain existing epoch protections. File checks, RAM/CPU limits, token caps, deadlines and output queue bounds remain unchanged.
