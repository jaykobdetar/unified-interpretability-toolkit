# Model and inference milestones

This lane starts from clean release commit `a2d7918133698cfa437851e01a1193ad6390628c`. Milestones are separate commits for parent review. Source contracts and fixture tests do not qualify a real model or advertise inference readiness.

## Ownership and dependencies

The model lane owns architecture/storage descriptors, `tools/inference_*.py`, `tools/live_inference.py`, and the owner registry/acquisition and worker adapter in `tools/atlas_host`. The performance lane owns shared runtime/resource configuration and Rust server/rendering code. The data lane owns workspace exports and experiment archive import. Changes to `web/inference.js` require agreement about the precise sections; no model lane UI change is included in the first milestone.

No new Rust dependencies or vendored libraries are needed. Pure modules use the Python standard library. Execution uses the existing separately installed, pinned inference requirements; built-in model classes only. No model-supplied Python, pickle, `trust_remote_code`, or automatic precision conversion is allowed. A pinned configuration describes coordinates, not runtime compatibility, installed-file integrity, resource fit, or execution permission.

## Sequence

1. Configuration descriptors: separate explicit built-in Llama, Qwen2, and Qwen3 mappings, including nondefault head dimensions, Qwen2 projection biases, Qwen3 Q/K normalization vectors, tied/untied output heads, and complete expected stored parameter shapes. Reject unsupported architecture/features; retain the existing pinned Smol worker contract. Bound config parsing and descriptor expansion. Test with small independent dimensions and no ML imports.
2. Owner acquisition and installed-model selection: validate repository name, full immutable revision, expected sizes and SHA-256, explicit license acceptance and pinned license file. Plan download/staging/receipt/cache/reserve space together. Download is an owner CLI action only; browser catalog/selection cannot authorize acquisition or mutate the registry. Any downloaded data remains unavailable until verified and explicitly enabled. Never use an arbitrary URL, model code, unsafe serialization, or inferred packed-weight encoding.
3. Stored-precision inference and residency: request explicit CPU/CUDA device and declared checkpoint dtype. Check actual tensors/device after loading and reject unavailable precision. Measure load/prefill/decode memory inside an admitted budget; configuration estimates never count as a measured fit receipt. Resident state is keyed by immutable content, adapter/runtime, device, and precision. Snapshot edited regions before mutation; restore and verify them in `finally`; fresh prompt/KV/capture state every run. Cancellation/reset can discard the owned process, and uncertain cleanup keeps its slot occupied. No later request can reuse uncertain/edited state.
4. Quantized formats: assess documented encodings independently from floating safetensors. Implement only bounded, declared standardized blocks with scales and exact byte-size checks. Packed storage is not a native dense edit mapping. Viewing/dequantization does not grant a quantized inference kernel or silently expand a model to FP32.
5. Qualification: run only after parent grants a remote slot and exact public model pins/license/byte budgets. Preserve user controls, matched-prefix causal labels, original source identities, and current bounded lifecycle safeguards.

## Proposed bounded remote qualification

One worker/model at a time, no browser/build overlap, loopback only. Parent supplies the RunPod slot; this lane never provisions, connects, downloads weights, changes credentials, or exposes ports independently. Proposed initial envelope: 10 minutes per model, at most 120 seconds per run, 128 prompt tokens, 8 generated tokens, one numerical CPU, at most 8 GiB process RAM and 6 GiB measured VRAM including allocator reserve. Parent and the shared resource owner must accept actual limits before execution. Keep the existing 25 GiB disk reserve and reserve acquisition plus staging explicitly. Stop before exhaustion rather than use an OOM test.

First qualify the existing exact Smol pin. Small Qwen candidates are Qwen2.5-0.5B and Qwen3-0.6B; they remain candidates until the parent approves exact full revisions and file manifests. For each: verify every source hash and full config/parameter topology; record runtime/package/GPU/dtype/attention identifiers; compare greedy cached decoding against uncached built-in forward with declared per-dtype tolerances; compare a selected output-head ablation with an independent pre-projection head-input oracle; show Qwen3 Q/K norm semantics explicitly. Run baseline → edit → restored baseline, then ordinary cancel/reset/model switch, requiring original source hashes and pristine resident parameters, fresh KV/capture state, and confirmed cleanup. Record cold/warm load time, peak RSS and CUDA allocated/reserved bytes and the minimum free headroom. No cross-model fit claims, failure traffic, live exploit probes, stress tests, automatic restarts, or unbounded sweeps.

Source review targets Transformers `v4.56.2` built-in [Llama](https://github.com/huggingface/transformers/blob/v4.56.2/src/transformers/models/llama/modeling_llama.py), [Qwen2](https://github.com/huggingface/transformers/blob/v4.56.2/src/transformers/models/qwen2/modeling_qwen2.py), and [Qwen3](https://github.com/huggingface/transformers/blob/v4.56.2/src/transformers/models/qwen3/modeling_qwen3.py). Qwen2 uses Q/K/V biases; Qwen3 normalizes projected Q/K per head. These differences require distinct adapters and tests.
