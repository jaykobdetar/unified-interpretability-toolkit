## Original-grant publication

Hosted static acquisition and reads retain the handler's original grant and a `StaticOperation` using the existing supervisor token and watch slot. Preparation, binding, serialization, bounded socket writing, watch joining and settlement remain under that operation. There is no renewed or nested publication grant.

Initial acquisition binds the complete native model before returning an active lease. A native ACK establishes native idle; it does not release publication ownership or freeze the HTTP meter. Checks surround the bounded write, watch joining and final settlement. A late refusal revokes readiness and leases, stops the exact selected reader and retains uncertain cleanup. Previously transmitted bytes cannot be recalled.

Trusted registry classification selects dense acquisition. Same-reader reuse still requires the original private metadata operation and current owner admission before a new lease. It retains the native cache lock and ongoing resource checks. A new reader independently repeats cold-start source, binary, resource, disk and cache checks.

The selected reader must remain live, nonfailed, identity-owned and present in the original CPU ledger through publication. A retired reader may be reaped while its CPU remains charged. Prospective candidate refusal preserves a valid old reader. Details and retained regression coverage are in [DENSE-STATIC-REVIEW-FIXES.md](DENSE-STATIC-REVIEW-FIXES.md).

## Resource and cache semantics

Each reader retains its last successfully settled cumulative CPU watermark, initially zero. New requests charge debt since that watermark together with original HTTP/provider CPU accounting. Observation and ACK do not rebase it. Old-reader cleanup and new startup retain distinct child series under one grant.

The existing idle observer samples and refuses at its allowance. This is not continuous proof of zero idle CPU. Lifetime callbacks can signal their exact owned children without acquiring the HTTP application lock. Failed token, watch, child or stream cleanup remains reachable until confirmed.

The structural binder checks the configuration-derived catalog. Admission separately checks native owner name and coherent idle, fresh-hash, calibration and cache claims. Uncalibrated statistics remain null. Valid saved statistics may be nonzero; native cache validation remains responsible for its own schema, source and checksum checks. No new payload scan or statistics calculation is claimed.

Cache preflight checks the existing lock without writing; native open repeats and retains the exclusive lock. Source updates require the qualified cooperative owner/filesystem protocol. The implementation does not establish exclusion against an uncoordinated external writer or generalize the recorded local filesystem evidence to other platforms.
