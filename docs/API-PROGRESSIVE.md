# Additive progressive contract

The original complete-calibration API is preserved in `API-v1-frozen.md`. This implementation advertises `api_version: 1` and `extensions: ["progressive-calibration-v1"]`; the adapted frontend explicitly supports the extension.

`GET /api/model` succeeds as soon as headers/index are validated. Before complete global calibration, `global_max` is null and `calibration_complete` is false. Each catalog tensor has its own `calibration_complete`, nullable `max_abs`, and nullable `median_nonzero_abs`. Source coverage, calibration coverage, and rendered tile coverage remain separate. `source_complete` means complete structural/header/index coverage, not full SHA verification. Fresh hash counts are zero unless this same server was started with `--verify-sha true`. `sha_hashed_shards` counts completed full-shard hashes. `sha_expected_matched_shards` counts only `matches_saved_expected_sha == true`; `sha_missing_expected_shards` counts freshly hashed shards without a saved expectation (`null`). The compatibility field `sha_verified_shards` equals `sha_expected_matched_shards`, never the hashing count. A saved expected-hash mismatch fails verification/startup; local expectations are not newly authenticated upstream. Saved identity validation and fresh hash information remain explicit.

`POST /api/calibrate?tensor=ID` with `X-Atlas-Local: 1` queues complete calibration of one selected tensor; it returns 202, or 200 if already calibrated. `POST /api/calibrate?all=1` requests the remaining tensors. Work is serialized and persisted after each tensor. The request queue is bounded; 503 means retry. A full scan yields to queued work between tensors. An individual tensor scan or tile is not interrupted mid-computation by a view change; closed queued tile clients are discarded before starting work.

`GET /api/view` succeeds for tensor rules once the complete selected tensor is calibrated. Any requested global rule returns 503 until every tensor is calibrated. No provisional global bound or partial-tensor legend is used. `GET /tile` obeys the same readiness requirement. It returns PNG plus `X-Atlas-Factor`, `X-Atlas-Cache`, `X-Atlas-Seconds`, and `X-Atlas-Source-Bytes`. A full numeric queue returns 503. Request errors return JSON with `error` and a 400 status; unknown static endpoints return 404.

`GET /api/inspect` always permits a valid native address after opening. Before a requested transform is ready, that transformed field is null and `transforms_ready` is false. `raw_exact`, dtype-sized `raw_hex_le`, `dtype`, `element_bytes`, `classification`, `shard`, `byte_offset`, and `native_indices` are available independently of calibration. `bf16_hex_le` is present only for BF16 and null for F16/F32. `raw_exact` is a full mathematical decimal expansion for finite BF16/F16/F32, rather than only a shortest round-trip rendering. Signed zero is preserved. Finite calibration is refused if a source contains NaN/Infinity; raw inspection can still describe the stored bytes.

The frontend defaults to local linear/asinh when global calibration is unavailable; it explicitly labels this state. It never places a local bound under a global legend. Global options enable after the full scan. It retains the reference's epoch/abort handling, clears stale panels/inspections, and synchronizes native image coordinates.

The server only binds 127.0.0.1, validates the loopback Host header, rejects cross-origin/cross-site requests, sends no CORS grants, serves a fixed embedded-asset allowlist, and has no model-path browsing or selection HTTP endpoint. Model selection is a local CLI/launcher operation. Request headers and queues are bounded. This is a local viewer, not a production internet-facing HTTP server.

Rust intake admits at most four pending header readers on its existing thread, with an 8 KiB header cap, a 0.5-second absolute receive deadline, and bounded read/admission work per loop. Excess admission receives a best-effort 503 with `code: admission_full` before closing. Completed headers enter a four-slot queue serviced by one fixed I/O dispatcher with a 2 MiB stack. A full dispatch queue returns best-effort 503 with `code: dispatch_full`. Intake never waits for metadata/filesystem work or response delivery: overload/input-error replies use one nonblocking write and close. Both dispatcher and numeric-worker responses have a single 3-second write deadline covering all header/body partial writes. A slow earlier response therefore does not consume another admitted reader's receive budget. Recoverable accept errors use finite capped backoff; fatal bind/listener errors remain errors. These are scheduling-aware bounds, not a hard real-time service guarantee or a bound on filesystem/numeric operation duration. Numeric execution stays on one worker with eight queued jobs, within the same CPU affinity and process-memory cap. All threads and sockets belong to the same owned Rust process; no independently running service is added.

Query decoding preserves literal Unicode, valid percent-encoded UTF-8, and `+` as query-space. Malformed escapes and invalid decoded UTF-8 return ordinary 400 errors. Decoding does not expand the static path allowlist.

A missing cached tile is removed from entry/byte accounting and regenerated from the unchanged validated source. Other cache read errors discard stale indexing but remain explicit errors; eviction deletion errors other than missing files preserve accounting and surface. Cache reads stay bounded. Atomic cache/statistics writes reserve a unique same-directory temporary file, sync before rename, and clean up only their own temporary after a failed write. Cleanup errors remain visible. Calibration writers prepare a prospective snapshot and publish it before exposing it to `stats`, `global`, model metadata, or completion responses. A failed publication leaves prior readiness unchanged and remains retryable. Readers can continue using the prior committed snapshot while publication waits. Existing saved calibration and source files remain intact until successful replacement.

## Tensor magnitude extension

`/api/model.rules` additionally advertises `tensor_magnitude`. Either `left` or `right` in `/api/view` and `/api/inspect`, and `rule` in `/tile`, accepts it. Like other tensor rules it requires completed selected-tensor calibration, with no global calibration requirement. Raw inspection remains available before calibration (transformed fields are null).

The formula is `abs(x)/M` with exact complete-tensor `M=max(abs(x))`; for `M=0` every field value is zero. Pooling averages transformed original values before coloring, including only real edge addresses. The unsigned field range is `[0,1]` (all-zero `[0,0]`). The legend has `min=0`, `zero=0`, `max=M`, `s=null`, `scope="complete original tensor"`, `palette="sequential-purple-v1"`, `field_min=0` and `field_max=1` (or zero for `M=0`). `units` distinguishes native absolute raw weight from pooled mean absolute raw weight. The palette linearly interpolates RGB `(247,244,249)` to `(84,39,143)` using the same ties-to-even rounding as the signed palette. No display-specific contrast rescaling occurs.

CLI example: `tile --model MODEL --cache CACHE --tensor ID --rules tensor_magnitude,tensor_linear --level LEVEL --x 0 --y 0 --out PREFIX`. Numeric `.f64le` and rule-specific PNG outputs agree with API tiles. The existing cap of four simultaneous rule fields per CLI request is retained; use multiple calls if exporting all seven rules. Vectors remain one native row. Fine tiles and coarse overviews share this exact renderer.

Tile cache namespace is `rust-rgba-v5-exact-json-f64-row-sums-subfilter`; each key includes source identity, renderer version, tensor ID, rule ID, level, tile coordinates and exact legend JSON. Old renderer keys are never reused; old files remain within the existing eviction budget. Formula lookup cache keys include dtype, rule, bound and asinh scale. Calibration schema is 4; it records dtype, exact robust clipping count and BF16/F16 histogram digest. Percentile lookup keys additionally bind source identity, tensor ID and histogram digest. HTTP responses continue to use `Cache-Control: no-store`, and stale frontend tile events remain isolated by view epoch. Existing four rule formulas and signed palette pixels are unchanged.

## Robust and percentile rule extension

`tensor_robust99` accepts BF16/F16/F32; `tensor_signed_percentile` accepts BF16/F16 only. `/api/model.rules` exposes `supported_dtypes` and the reason F32 percentile is unsupported. Tensor catalog entries expose percentile `rule_status`, Q99, exact robust clipping count and quantile precision metadata. Unsupported percentile view, tile and CLI requests fail explicitly; raw inspection still succeeds with a null transform and `transform_errors` reason. No alternate rule is substituted.

Robust legends report Q99, effective divisor D (`Q99` or `1`), the zero-quantile fallback, strict clipped count/fraction and saturation bounds ±D. Percentile legends span dimensionless [-1,1], explain ties and zero handling, and carry the exact histogram checksum. Both rules transform original native values before pooling. See [RULES-STUDY.md](FORMATS.md) for formulas, precision and readiness limits.
