# Architecture

Unified Interpretability Toolkit has independent local entrypoints. The viewer is the default; optional coordinators add separate ownership and compute lifetimes.

| Layer | Location | Responsibility |
| --- | --- | --- |
| Native reader and renderer | `src/` | Validate safetensors structure; stream bounded source bands; calibrate exact statistics; transform/pool/render tiles; inspect original bytes. |
| Loopback transport | `src/server.rs` | Fixed embedded assets and bounded HTTP queues/deadlines, Host/Origin checks, one numeric worker. |
| Browser viewer | `web/app.js`, `web/atlas-tools.js` | Source-bound selection, synchronized OpenSeadragon panels, legends, exact inspection, exports and navigation state. |
| Checkpoint comparison | `src/comparison.rs`, `web/comparison.js` | Ordered A/B identity, shared original scales, separately labeled differences; no inference edit targets. |
| Optional inference | `tools/live_inference.py`, `tools/inference_worker.py` | Loopback coordinator and one disposable pinned CPU model worker; explicit owner lease, admission, cancellation and cleanup. |
| Optional regional analytics | `tools/analytics/` | Bounded BF16 windows, seeded controls, explicit small SVD; serialized against inference. |
| Experimental local host/profile | `tools/atlas_host/`, `tools/profile_atlas.py` | Owner registry, fixture selection, bounded whole-slice profiles, sealed snapshots, source leases and worker ownership. |

## Source and cache boundary

Model files are opened read-only. Safetensors headers/indexes establish supported extents before payload access. Source identity and explicit slice binding travel with results; stale responses cannot replace a newer selection. Unsupported dtypes/shapes remain unavailable catalog entries. Original scalar bytes stay distinct from derived transforms and differences.

`Source::open` orchestrates index loading, shard-name collection, bounded shard/header reads, tensor-entry validation and final catalog validation. The private steps in `src/source.rs` keep the same validation order and error text. Shard parsing appends to the caller's existing tensor buffer; it does not build a second catalog. The original ordered source-identity expression remains in `Source::open`, followed by the final fingerprint check.

Tensor, calibration and comparison metadata hold immutable `source::Format` values from `src/source/format.rs`. Each retains the exact original string and parses its optional numeric interpretation once when constructed or deserialized. Clones retain that interpretation; numerical consumers use the cached enum through `Dtype::parse`. String and `&str` parser inputs remain supported. Serialization and debug output delegate to the original string, including unsupported catalog encodings, with no added wire field or validation. The Rust metadata field types are now `Format`; their private spelling and cache cannot be mutated independently. Source validation order, calibration formats and identity expressions remain unchanged.

Native operations share `error::Error` through the crate's `Result` alias. One table in `src/error.rs` defines owned refusals and the existing I/O, JSON, integer/range/array, allocation, UTF-8, NUL and clock families. Payloads remain boxed. Display, Debug and source behavior delegate to the original payload, including the original source depth; no category text is added to messages. Existing guard bodies, HTTP status/envelope construction and fatal CLI prefix/exit mapping remain at their callers. This changes the internal Rust error carrier from an opaque trait object to the typed enum; it adds no wire field or validation.

Native CLI intake uses `src/command.rs` for exact command IDs, public/comparison help order, startup classification and the existing key/value grammar. The catalog distinguishes the eight standalone commands from comparison/private commands; unknown IDs keep the original legacy classification and caller validation order. `resources::StartupScope` consumes that pure catalog, which imports no resource policy or I/O. Option parsing preserves values, ordering and refusals. Defaults still resolve at their existing callers; dispatch and route behavior retain their original branches.

All twenty-three static native CLI fallback facts share that command declaration: intake cache/hash choice, serving port, comparison defaults and overview/tile/bench defaults. Each context keeps its own constants. Help consumes seven of those same values, including its original relative cache spelling. Callers retain option lookup and cloning, required options, both dynamic level defaults and refusal order. These facts do not insert defaults into parsed options or add validation. Audited per-command option declarations preserve documented common names and the private worker required/restore sets; ordinary intake validation remains unchanged.

The eight native and five comparison dispatch branches consume the same typed command catalog. Lookup happens at each original match location, after intake and comparison construction/tensor parsing. Unknown IDs retain the original fallback, including root routing of unknown `compare-` prefixes, and case remains significant. Metadata/profile-worker early handling and serve hash opt-in consume exact catalog IDs at the original intake locations; unknown compare-prefix routing stays separate. The pure src/api.rs declarations share seven public viewer paths, five comparison paths and eight private IDs/parameter sets, including broker-only binding. Dispatch/status/reuse and private admission consume those facts without changing arm bodies, guard order, refusals or public validation. See [native interface declarations](NATIVE-INTERFACES.md) for the repository caller audit and distinct private/public sets.

Calibration scans complete original tensors. Opening a checkpoint reads headers, not all payloads. Tensor rules become ready after that tensor's calibration; global rules need the whole supported checkpoint. Source changes invalidate cached results. Cache paths must be outside model trees; cache locking prevents concurrent mutation. Local checksums detect inconsistent cache content but are not authentication. Explicit full hashing is available through the native `verify` command.

The ordered native rule catalog lives in `src/rules.rs`. Each definition holds its public ID, title, formula, checkpoint or tensor scope, transform, required statistics and supported numeric formats. Metadata, legend controls, pointwise mapping, percentile admission and palette selection consume those typed facts. `render::RULES` and the existing public rendering functions retain their interfaces and serialized metadata. Mapping still transforms each original value before pooling; sliced views use complete original-tensor calibration. Exact percentile ranks remain limited to BF16/F16, with the existing F32 refusal and histogram checks.

Slice bindings and descriptors are constructed from typed borrowed records in `src/slice/response.rs`, then converted to the existing JSON value interface. This conversion uses only string, integer and array values and introduces no fallible serialization path. The identity-domain inputs and their ordered JSON derivation stay in `TensorSlice::new`; they are separate from response field construction. Held UTF-8 byte vectors protect both the identities and the serialized public responses.

Native scalar inspection builds a typed record in `src/server/response.rs` at that same JSON boundary. It retains every field, including the nullable BF16 byte spelling, exact original decimal, native indices, source binding and separate transform values/errors/readiness. The conversion introduces no fallible serialization step. Request/source validation, original-byte reads, rule admission, calibration checks and classification remain in `server::inspect` before response construction; fixed response witnesses cover finite and nonfinite values, selected planes and ready/unready transforms.

Small viewer readiness responses use typed selected-tensor, coverage and status records in `src/state/response.rs`. They convert directly to the existing JSON value shape, including null statistics, exact rule-status text and the redacted calibration error. `State::status` retains source validation, calibration/progress/tile-cache acquisition order and the 16 KiB response check. Selected-tensor conversion still occurs before tile-cache acquisition; identity derivation and all readiness/count calculations remain at their existing caller.

The native entrypoint in `src/main.rs` keeps help and argument validation ahead of resource configuration and model access. `run_args` selects the startup scope and opens the required source or state; private helpers parse option pairs, initialize custom resources and print metadata. Command dispatch delegates calibration, overview, tile output and benchmarking to separate functions. These stages retain the existing option defaults, validation order, command IDs and output fields.

## Resource and ownership boundary

Native operations use one CPU, a 768 MiB address-space limit, bounded source bands, bounded output/cache budgets, and memory/disk admission checks. The Python live coordinator, profile OS hooks and local hash verifier share the typed memory observation in `tools/atlas_host/memory.py`: one read selects the first exact `MemAvailable` field and converts KiB to bytes. Their existing module import names and caller-specific admission thresholds remain; missing or malformed fields and file errors retain their original exceptions. The shared module starts no work on import. Analytics child setup in `tools/analytics/runtime.py` also uses that memory reader. The worker retains its `configure` import name and calls setup before input processing: the same five-second kernel alarm, first admitted CPU, nice value and inherited address-space/CPU caps precede the existing 3.25-GiB memory gate. Numerical source reading and optional NumPy imports stay in the worker. Coordinators preserve their own lower work budgets and stop reserves. A caller never acquires another session's worker; unknown cleanup remains blocking. Only owned children are terminated/reaped. Logging/export requires explicit user actions.

The private native profile worker in `src/profile_worker.rs` admits its options and original grant before source access, then bounds and validates the candidate descriptor. A borrowed context passes the same source, identity, seed, value allowance and scan deadline to profile creation or restoration and bounded advancement. Final snapshot writing, sealing, source checks and the original deadline remain ordered before candidate output. The original model-identity expression stays in the entry function, and the owner still decides whether to publish the candidate.

The optional SVD parent also reads memory through `atlas_host.memory`, after its existing window and seed validation and before disk admission or child creation. Its original reserve, five-second parent timeout, worker command and one-thread numerical environment remain. The child calls the typed SVD setup in `analytics.runtime` before reading input; affinity, nice value and inherited address-space/CPU caps keep their order. This setup adds no child alarm or memory read. Request validation and the optional NumPy import remain inside the child, and both matrix computations remain unchanged in `analytics.svd`.

The generation experiment lives in `tools/atlas_host/inference_generation.py`. Its typed `GenerationBindings` receives the existing architecture dimensions, capture descriptions and observation callbacks from the worker for each call. The module imports only the standard library; opaque tensors and model/torch objects remain explicit third-party boundaries. `inference_worker.generate` retains its arguments and defaults as the compatibility delegate. Engine loading and pins, source verification, admission, dispatch and session ownership stay in the worker/coordinator. The original validation, prefill emission, greedy loop, capture hook, observation arithmetic and `finally` removal keep their order. Compatibility facade and worker/coordinator entrypoint packaging remain separate work.

The worker and coordinator use the five closed registrations in `tools/atlas_host/inference_experiments.py`: model-free prompt preview, sweep, prompt pair, edits comparison and generation. Every worker adapter receives the same typed `(Context, Request)` interface. The coordinator uses these registrations for its existing strict mode intake; the worker retains its existing unknown-mode generation fallback and branch priority. Preview dispatch happens after source verification and tokenization, before engine loading or loaded provenance, and receives no engine objects. Coordinator memory admission, job budgets, wire request order, public modes and session ownership retain their original policies. The registry adds no wire field or model registration.

The comparison experiment lives in `tools/atlas_host/inference_comparison.py`, including paired-step arithmetic and its nested callbacks. A frozen `ComparisonBindings` injects the current generation, paired-step, edit validation, model verification and edit application callbacks on each worker call. Compatibility delegates preserve signatures and default emission. The module imports the standard library and the engine-free experiment contracts only. Foreign engine/tensor objects and open legacy trace envelopes remain explicit `Any` boundaries; this does not claim a closed schema for every record. The original fresh-branch generation order, consumed-prefix alignment, raw FP32 score unions/deltas and trailing baseline records remain. Runtime comparison helpers retain their compatibility entrypoints. Broader service typing and compatibility entrypoint packaging remain separate work.

The services bind only to loopback. There is no hosted authentication/deployment architecture or general remote model browser. See [API semantics](API-PROGRESSIVE.md), [data/slice binding](DATA-VIEWER-CONTRACT.md), and [profile worker interface](profile-worker/PROFILE-WORKER-INTERFACE.md).

The [native invariant audit](NATIVE-INVARIANTS.md) records explicit unwrap/expect sites, existing mutex poison policies and the limits of repository-only unused-code evidence. It preserves the current caller contracts and lock behavior; deletion proof remains unfinished.

Viewer dispatch in `src/server.rs` retains connection expiry, bounded reuse framing, request parsing and eligibility checks before routing. Private functions handle calibration admission, tile queue admission, status/view replies and fixed assets. Tile admission transfers the same socket, lease and eligibility flag to the existing numeric queue; the other routes preserve their original response and lease lifetime. Header intake, dispatch and numeric work keep their existing queues and deadlines.

Comparison dispatch in `src/comparison_http.rs` validates the request and comparison identity before routing. Private functions handle tensor calibration admission, tile queue admission, model/view/inspect reads and fixed assets. Dispatch retains method checks and the existing status and error mapping; each stage keeps the same query defaults, queued socket ownership and response fields.

## Experimental owner fixture workflow

The owner registry uses `config/atlas-host.example.json`; its paths resolve relative to that config. `tools/atlas-model.py` supports local validation, registration, enabling/disabling, and owner receipts. It does not download models. Owner receipts include source paths and should stay local. The HTTP visitor catalog exposes opaque model identities instead.

```bash
python3 tools/atlas-model.py --config config/atlas-host.example.json validate-config
python3 tools/atlas-model.py --config config/atlas-host.example.json plan \
  --manifest fixtures/tiny-bf16/host-manifest.json
```

Registration and owner preparation are explicit operations. `tools/host_atlas.py` serves the fixture picker; `tools/profile_atlas.py --help` describes the profile entrypoint requiring the exact native binary SHA-256. Neither automatically makes arbitrary local models eligible. Default resource gates remain in force. Profile scans are explicit and bounded; partial coverage is labeled and not treated as representative sampling or full completion.

Current regression tests cover the source/ownership contracts using tiny fixtures and doubles. Prior bounded workflows are not proof of long-session, arbitrary-model, physical-mobile, fault-injection, or GPU behavior.

The pure `Architecture` value and geometry functions in `tools/atlas_host/inference_geometry.py` receive existing description, source/configuration records, capture labels and dimensions as explicit values. The injected operations in `tools/atlas_host/inference_engine.py` receive runtime classes/modules and verification callbacks; neither module reads pins or imports ML libraries. Compatibility delegates retain the original bundled-pin checks, public geometry signatures/defaults and lazy built-in runtime imports. Engine setup keeps its original one-thread/seed/determinism settings, offline safetensors load and verification order. Runtime and configuration records remain explicit foreign/open boundaries. This establishes the passed-value and engine boundary. Compatibility builders and runtime helpers retain their current defaults; ordinary package imports remain separate work.

The pure edit and observation operations in `tools/atlas_host/inference_edit_contract.py` and `tools/atlas_host/inference_observation_contract.py` receive `Architecture` through frozen bindings, together with existing source/shape/alias data, semantic labels and helper callbacks. Their compatibility modules retain exported constants, public argument defaults and late callback lookup in two explicit binding factories. Request validation, source and loaded-parameter checks, edit arithmetic, paired-output bounds and logit-lens union/delta rules preserve their original order and records. The contract modules import no pins, compatibility modules or ML libraries. Pair and sweep contracts also receive these held values before ordinary packaging.

The pure prompt-pair and sweep contracts in `tools/atlas_host/inference_pair_contract.py` and `tools/atlas_host/inference_sweep_contract.py` receive architecture dimensions, original source/shape data, limits and helper callbacks through frozen bindings. Compatibility facades retain argument defaults, exported constants and late helper lookup. Preview identities, vector metrics, projection ranges, deterministic plan controls/digests, record bounds and resource limits keep their exact implementations. Pair capture and sweep restoration/runtime loops remain unchanged. Four compatibility factories retain default legacy reads and also accept a held architecture for project callers. Ordinary package entrypoints remain separate work.

Worker generation/intake and coordinator metadata, admission and bounded record draining now receive the same held architecture through `tools/atlas_host/inference_services.py`. This pure module binds the existing edit, observation, pair and sweep contracts without pin reads or numerical imports. Four private compatibility factories accept an optional architecture; explicit calls preserve its object identity and keep architecture-dependent callbacks bound to it. Default calls retain existing exported values and late helper lookup. Two default entry builders capture worker/coordinator compatibility values, so six compatibility builders still read legacy data. Model verification, capture/restoration loops, wire records, request and resource limits, cleanup and direct script commands retain their existing behavior. This boundary describes the current pinned model; ordinary packaging and broader architecture extensions require separate work.

Geometry and engine implementations use ordinary `atlas_host.inference_geometry` and `atlas_host.inference_engine` imports. The old top-level module names remain compatibility aliases to the same module objects, preserving class identity, patches and shared late lookup. The package initializer has no runtime effects. Existing direct `python3 tools/...` commands keep using Python's ordinary script-directory search path and require no installation.
