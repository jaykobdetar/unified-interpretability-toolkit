# Private experiment archives

Enable **private experiment logging** to collect each subsequently accepted run's terminal outcome. Logging is off by default. Its bounded log contains at most eight runs and 1 MiB of UTF-8 JSON, with one visibly pending overflow record. Completion, cancellation, errors, limits and uncertain transport cleanup keep their distinct statuses. No record is silently dropped. Export and explicitly clear/discard before admitting further runs when the cap is reached.

Prompt capture requires its own consent. Generated outputs and activation captures remain private even when prompts are omitted. Unchecking prompt inclusion redacts existing records at download time; it does not remove the original in-memory data.

## Persistence choices

Without another opt-in, the log stays in this tab's memory. Explicit JSON downloads provide portable files.

**Save private logs in this browser profile** enables automatic persistence of recorded terminal outcomes on this origin. Separate **retain captured prompts** consent is unchecked by default and applies to both browser storage and the selected journal file. Only prompts already captured with consent can be retained. Turning retention off rewrites the saved log with prompt fields redacted. Logging itself must still be enabled for new accepted runs to be collected.

Browser storage has at most eight archive slots, each capped at eight runs / 1 MiB. Slots have random archive names; worker session capabilities, paths and process ownership are excluded. Browser saves, both deletion controls and owner-key persistence use the same Web Lock to serialize origin-wide quota checks and storage updates. Reads create no owner keys. A pending deletion blocks new work until it finishes; deletion failure preserves the in-memory records and exposes recovery. Unsupported storage/locks and quota failures produce an explicit error and pause new runs; completed in-memory records stay available for export, retry or disabling persistence. Browser storage can be cleared or evicted; it is not a guaranteed filesystem journal. Others using this browser profile can access its data.

Reload never restores records, enables logging, resumes computation or renews file permission automatically. **Restore this tab's saved log** explicitly appends its archive. After closing a tab, **Find saved private archives on this origin** lists bounded archive names; select one and explicitly restore it into the current tab. This copies historical records without adopting any live worker, changing run inputs or taking over the original tab's storage slot. A stale own-slot write is refused if another tab has changed its saved contents. Delete a selected saved archive explicitly to free a slot; this affects browser data, not worker sessions or files. Restoring/exporting never silently clears records. Refused imports leave the current log unchanged.

On compatible secure-context browsers, **Choose file for automatic private log updates** opens the browser's explicit file picker. After selection, each terminal logged outcome and later cleanup confirmation rewrites the bounded `weight-atlas-session-log-v1` JSON journal. The handle stays in memory and is forgotten on reload. Permission revocation or write/close failure retains the in-memory record, pauses new runs and offers save/retry/export/stop-journal recovery. A new run cannot start while the write is pending. The journal is a bounded snapshot, not an unlimited append-only history. A cancelled picker leaves the existing sinks unchanged. Unsupported browsers show that automatic filesystem recording is unavailable and retain the download/browser options. Closing the tab during a pending write can interrupt persistence; wait for the saved status before closing.

## Import and reproducibility

Select one experiment or session-log JSON and click **Import into this tab's log**. The first explicit import or restore loads one fixed trusted codec asset from this viewer origin. It is excluded from the startup bundle, works with the existing self-only script policy, and has a 15-second initialization limit. Load failure leaves records unchanged and requires an explicit retry. **Cancel archive import / restore**, or resetting the existing worker view, invalidates a pending import; late file reads or codec initialization cannot append its records. Imported data never starts a model run, accesses source files, restores worker sessions or replays a request. It appends archived records, with a separate unchecked prompt-retention choice; otherwise prompts, prompt IDs and prompt-bound digests are redacted. The same choice applies to browser-archive restoration.

Import validates v1 schemas, exact UTC timestamps, terminal state, finite typed leaves, generation budgets and token IDs, native edit indices/ranges, capture/candidate/vector caps, mode-specific requests, sweep expansion/trace/coverage counts, source fields, derived settings/privacy/limits and duplicate keys. Session metadata and declared byte/run caps must fit the actual input. Oversized, excessively nested, unknown-field or worker-ownership data is refused. Import capacity is checked atomically against existing records. Historical identity/runtime/cleanup claims remain unverified; an archive is not a newly authenticated model or a proof of completed cleanup. Legacy logs with missing model identity remain historical records and cannot establish a reproducible pinned source.

A prompt-inclusive archive retains ordered edits/targets, seed and greedy settings, model identity when supplied, runtime versions, captures, coverage and incomplete outcomes. Exact rerunning also requires the same pinned model/runtime and explicit manual request review through the normal current admission path. Redacted archives cannot reproduce the exact private prompt. Prompt-set sensitivity, partial coverage and changed-prefix differences keep their existing interpretation limits.

Safe doubles cover quota/permission rejection, bounded file writes, explicit reload/restore, queued shared-owner save/delete ordering and stale-save refusal, lazy-codec failure/retry/timeout/cancel/reset ordering, and absence of model execution from imported data. Independent sweep-plan producer compatibility covers subset and full-layer plans. Bounded synthetic [browser mechanics and actual downloads](DATA-BROWSER-QUALIFICATION.md) are checked. Native picker and multiple-download permission interactions and actual inference-coordinator integration remain separate required checks.
