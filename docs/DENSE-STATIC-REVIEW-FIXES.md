# Selected publication and reacquisition checks

The dense path revalidates the exact selected preparation, current same-owner private policy/binary/evidence seals and sampled identity-owned reader health before writing, after writing and after watch joining. Complete selected binding is required before publication. A selected child must remain live, nonfailed and in the original CPU ledger. A retired child can be reaped while its CPU remains charged.

A late refusal revokes readiness and leases, stops the exact selected reader and retains cleanup until confirmed reap. This includes reader reuse that sends no native command. Bytes already transmitted cannot be recalled. Refusing a prospective candidate continues to preserve a valid old selection.

Trusted registry classification determines whether acquisition needs dense admission. Every dense acquire, including same-reader reuse, requires the original private metadata operation and repeats current owner admission before creating a lease. Public picker hints cannot select an ungated path. Reuse keeps the existing cache lock and ongoing resource checks; new readers independently repeat cold-start checks.

Valid reuse keeps the original HTTP grant, supervisor token and watch through final publication. It neither repeats the full native catalog nor acquires a nested grant. Disabled, changed or stale private policies cannot grant a lease or publish readiness.

Retained regressions cover late source/seal refusal, changed or disabled owner policy, selected-reader loss, successful publication, retired-old/live-new switching, refused/foreign/disabled reacquisition, original-grant reuse and late reuse cleanup. The accepted independent source review reports 203 passing pure Python cases and 25 passing Node cases. Those checks used inert clocks/readers/transports and tiny synthetic data; the separate lifecycle evidence and its limits are described in [STATIC-QUALIFICATION.md](STATIC-QUALIFICATION.md).
